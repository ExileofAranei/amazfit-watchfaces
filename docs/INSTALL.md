# Установка на часы и симулятор

Источники: docs.zepp.com (guides/quick-start/preview, guides/tools/zepp-app, guides/tools/cli,
guides/tools/simulator/download, guides/faq/simulator-faq) и README `@zeppos/zeus-cli` 1.10.2.

## 1. Телефон: аккаунт Zepp и привязка часов

Скорее всего, у тебя это уже сделано.

1. Установи приложение **Zepp** (Google Play / App Store).
2. Зарегистрируйся или войди в **аккаунт Zepp**.
3. Привяжи Amazfit Active Max по подсказкам приложения.

## 2. Телефон: режим разработчика

Zepp → **Профиль** → **Настройки** → **О приложении** → нажми на иконку Zepp **7 раз подряд**, пока
не появится всплывающее окно. После этого в Профиле у привязанных часов появится пункт
**Developer Mode / Режим разработчика** со сканером QR-кодов.

Выключить: Профиль → Настройки → убрать опцию Developer Mode.

## 3. Аккаунт разработчика (Zepp Open Platform)

`zeus login` спрашивает логин и пароль **Open Platform**: https://developer.zepp.com.
Войди туда своим аккаунтом Zepp. Если сайт попросит завершить регистрацию разработчика (никнейм,
согласие с условиями), пройди её. Публиковать что-либо в магазин для этого не нужно.

> Не проверено: нужен ли для `zeus preview` зарегистрированный в консоли `appId`. В `app.json` у нас
> временный `1080001`. Если preview откажет из-за appId, создадим приложение-циферблат в консоли
> и подставим выданный id.

## 4. Компьютер: вход в Zeus

Всё запускается в Docker. Node и npm на хосте не нужны: нужны только Docker и скрипт `./wf` в корне репозитория.

```bash
cd ~/projects/amazfit-watchfaces
./wf install    # один раз: собрать образ и поставить зависимости
./wf login      # печатает ссылку для входа
```

Открой ссылку в браузере Windows, войди. После входа браузер перейдёт на «callback»-адрес: скопируй
его целиком из адресной строки и вставь в терминал. Проверить вход: `./wf status`.
Логин хранится в Docker-томе `zepp-auth` и переживает перезапуски контейнера.

## 5. Установка на часы

```bash
./wf preview dm-replica
```

Команда соберёт циферблат и покажет в терминале QR-код. Дальше на телефоне:

1. Zepp → Профиль → твои часы → **Режим разработчика** → **Сканировать**.
2. Отсканируй QR с экрана. Циферблат загрузится на часы через телефон.
3. Часы должны быть рядом, с включённым Bluetooth, и подключены к Zepp.

Если QR в терминале не сканируется (мелкий шрифт, тёмная тема), увеличь окно терминала или уменьши
масштаб шрифта.

**Альтернатива без облака:** `zeus preview --local` (внутри `./wf sh`). Пакет раздаётся с компьютера по локальной сети,
QR вида `zpkd1://`. В WSL2 с `networkingMode=nat` телефон не увидит WSL напрямую, поэтому основной
вариант — обычный `preview`.

## 6. Что проверить на часах

- Время и секунды, переход минут.
- AOD: включи «Всегда на экране» в настройках часов и опусти руку.
- Дата, день недели и месяц по-русски. Порядок дней недели (понедельник первым) пока не подтверждён.
- Погода (иконка и температура, в том числе отрицательная), заряд, шаги, калории, пульс, дистанция.
- Значок будильника появляется, только когда будильник включён.
- Тапы: пульс, шаги, калории, погода, будильник.

## 7. Симулятор (необязательно)

Нужен для быстрой проверки без часов. Ставится в WSL (Ubuntu 24.04, окно выводится через WSLg).

```bash
cd /tmp
curl -LO https://upload-cdn.zepp.com/zepp-applet-and-wechat-applet/20260717/simulator_2.1.2_linux_amd64.deb
sudo apt install ./simulator_2.1.2_linux_amd64.deb

# Ubuntu 24 (noble), из simulator FAQ
sudo apt-get install -y libcapstone4 libsdl2-dev libaio-dev
[ -e /usr/lib/x86_64-linux-gnu/libaio.so.1 ] || sudo ln -s /usr/lib/x86_64-linux-gnu/libaio.so.1t64 /usr/lib/x86_64-linux-gnu/libaio.so.1
sudo chmod 4755 /opt/simulator/chrome-sandbox
```

Запуск симулятора: `/opt/simulator/simulator` (или из меню). Внутри скачай эмулятор устройства:
Active Max, если он есть в списке, иначе любой круглый 480×480. Запусти его, затем:

```bash
npm run dev -w faces/dm-replica
```

Не проверено: работа симулятора под WSLg и наличие профиля Active Max.
