# Стиль кода

## Имена файлов

Имена исходников, документации и ассетов пишем в `kebab-case`. Используем строчные латинские буквы и цифры, слова разделяем дефисом. Например, `segment-clock.ts`, `code-style.md` и `weather-clear-night.svg`. Одно слово или число тоже подходит: `readme.md`, `layout.ts`, `0.svg`.

Расширения пишем строчными буквами. Сохраняем служебные части имён, которые распознают инструменты, например начальную точку в `.gitignore` и суффикс `.d.ts` в `zos.d.ts`. Файлы инструкций для агентов сохраняют ожидаемые имена `AGENTS.md` и `CLAUDE.md`.

Для отдельного глифа используем его код Unicode: букве Б (U+0411) соответствует `u-0411.svg`. При переименовании файла обновляем импорты, пути в конфигурации и ссылки в документации.

## Сообщения коммитов

Для новых коммитов используем [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/). Заголовок начинается с типа изменения, затем идут двоеточие, пробел и краткое описание. При необходимости после типа указываем в скобках область изменения, например `segment` или `tooling`.

```text
feat(segment): добавить постоянный экран AOD
fix(segment): исправить интервал между цифрами шагов
docs: описать установку циферблата через QR-код
```

Тип выбираем по назначению изменения:

- `feat` — новая возможность, `fix` — исправление ошибки.
- `docs` — документация, `test` — тесты.
- `refactor` — изменение структуры кода с сохранением поведения, `perf` — оптимизация производительности.
- `style` — форматирование исходного кода, `build` — сборка или зависимости, `ci` — конфигурация CI, `chore` — обслуживание репозитория.

Для несовместимого изменения ставим `!` перед двоеточием, например `feat(tooling)!: изменить формат конфигурации циферблата`. Подробности перехода можно указать в конце сообщения после `BREAKING CHANGE:`.
